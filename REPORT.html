Нове правило C5 — контракт compose ↔ config для пулу БД

Додано правило C5 у tools/check-deploy.mjs та тест у tools/test/check-deploy.test.mjs (action item #1 з docs/postmortem.md).

  • Кожен довгоживучий сервіс compose має мати DB_POOL_MAX у environment.
  • Кожен DB_POOL_* у compose має бути змінною, яку читає app/src/config.js (DB_POOL_MAX, DB_POOL_WAIT_MS).
  • Разові job (restart: "no", без ports:) виключені.
  • Правило ловить клас проблем, а не лише цей інцидент: будь-яке перейменування / помилка в імені DB_POOL_* дає FAIL. Тест містить фікстуру інциденту (DB_POOL_SIZE замість DB_POOL_MAX) → FAIL, і коректний compose → PASS.

Існуючі правила не послаблено, сервіси не видалено, перевірки не вимкнено.
